# 進度盤點

`/recall` 只負責查清楚目前做到哪裡，並用 PDF 回報。它不負責上版或開始下一項工作。

## 不可越界

- 不開始、規劃或實作下一項功能。
- 不修改程式、文件、設定、卡片、PR 或看板。
- 不提交、合併、推送、部署、發版、建立 tag 或切換、建立、刪除分支。
- 不清理工作樹，也不移動或刪除任何檔案。
- 只盤點未完成工作；不為了讓報告好看而把它補做完。

## 收尾流程

1. 讀適用的 `AGENTS.md`，確認 repo、目前分支、remote、工作樹及本次任務範圍。
2. 用實際差異、提交、測試、產物、PR 與 CI 核對成果。文件、LOOP、commit 訊息只作線索，不單獨當成完成證據。
3. 讀取現有檢查結果；只有為了判斷現況且不會改變工作區或外部狀態時，才重跑必要檢查。
4. 分開回報本機、提交、PR、CI 與部署狀態，不把其中一項完成推定成其他項也完成。
5. 產出 PDF 狀態報告。查不到時照實寫「未查證」，不可用推測補齊。

## PDF 狀態報告

1. 讀取並執行 PDF 技能，使用 `scripts/render_recall_pdf.py` 產生 1–2 頁橫式繁中 PDF。JSON 與 PDF 放在 `~/.local/state/recall/reports/`，不交付 HTML 或中間排版檔。
2. 第一頁直接回答：已完成什麼、還沒完成什麼、為什麼停下、目前工作環境是什麼狀態。
3. 用大數字、狀態表、簡短時間線表達；文字一句一事。至少分開顯示本機修改、commit、測試、PR、CI 與部署。
4. 數字只用實測或可讀回的結果。無法證明是停機、技術困難或外部阻擋時，寫「原因無紀錄」，不可猜。
5. 標明盤點時間、範圍與證據邊界。未完成、執行中、外部阻擋與未查證不得標成完成。
6. 以 `pdfinfo`、`pdftotext`、`pdftoppm` 驗證頁數、文字可搜尋及每頁視覺版面，修正截斷、重疊與過小文字。
7. 最後只回覆一句結論與 PDF 連結，不在聊天重貼整份報告。

## 完成判準

- 已完成任務有可核對的提交與檢查結果。
- 本機、遠端、CI、部署狀態沒有混為一談。
- PDF 能讓非工程人員一眼看懂已完成、未完成與停下原因。
- 沒有改動工作內容、Git 狀態或外部系統。
