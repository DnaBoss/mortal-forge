# 製作與成本

## 素材先分類

| 類型 | 優先路線 | 主要驗收 |
| --- | --- | --- |
| 小道具、雕飾、遠景物 | 現有合格素材優先；缺少時用 AI 圖轉模型 | 輪廓、背面、尺寸、材質、碰撞 |
| 門窗、柱梁、可進入房屋 | 可重用建築元件與人工尺寸控制；AI 做局部裝飾 | 接縫、門洞、走道、地面、碰撞 |
| 主角、具名 NPC、四足生物 | 小樣測試後再決定 AI 底模或人工 | 關節網格、骨架、權重、動作穿插、風格 |
| 同款不同顏色／磨損 | 重用模型與共用材質，必要時只重貼圖 | 風格一致，不新增無謂幾何 |

這是本案工程選擇，不是廠商能力排名。不要把遊戲品質目標降成可辨識粗模，也不要因上一次失敗便禁止所有生成技術。

## 省費順序

1. 搜自己的素材清單：看來源、授權、已驗收狀態與可改造程度，不能只比名稱。
2. 做一頁素材需求：物件單獨、輪廓完整、光照均勻；要旋轉看的物件提供一致的前／側／後視圖。別把整張場景、多個不相關物件或互相矛盾視圖送成單件。
3. 固定風格範例、實際尺寸、配色、材質種類、可動部件和鏡頭距離。武器、門扇、輪子等要動的部分先拆開設計。
4. 第一輪每服務每件最多兩個形狀候選，先選最接近的；第二輪只有明確可修的差異才做。這是預設上限，使用者可調，不是保證品質的次數。
5. 除非端點或方案不允許，落選形狀不付材質、骨架或動畫費；不要一次串完整流程再發現輪廓不對。
6. 依鏡頭決定貼圖解析度，從足夠的低檔開始；高解析不會修好錯誤結構。形狀正確但材質錯誤，只換材質或本機修整。
7. 兩次相同缺陷仍在，記錄失敗原因並改參考、拆件、改工具或人工；不為湊滿額度繼續抽。

## 費用如何計算

先保存報價日期、服務、網頁或 API、帳戶方案、模型實際版本、操作、加價選項及幣別。網頁訂閱費與 API 費分欄。免費額度、已購額度及即將到期額度也分開。

```text
剩餘可承諾支出 = 授權總上限 - 已確認支出 - 進行中預留 - 未知支出預留
每件合格現金成本 = 本批實際現金支出 / UE 驗收通過件數
每件完整成本 = (分攤訂閱 + API費 + 儲存費 + 整理工時估值) / 合格件數
```

授權可採貨幣上限加供應商點數上限；換算率未確認不能只憑點數宣稱美元成本。進行中已凍結點數不可再當可用；未知提交保留最壞支出直到對帳。退款僅在帳單確認後沖銷；成功但不好看仍是支出。

訂閱本月買了卻只使用一部分，計算整月成本時須包括未用完額度；單件邊際成本另列，不能兩種算法混用。零合格時報總支出及零合格。

### 可重算的省費範例

官方 Meshy API 於 2026-10-19 列示：`meshy-7.1` 純形狀 20 點，形狀含 2K／4K 材質 30 點，後續材質 10 點。假設做 10 個形狀只留 3 個：

- 全部直接含材質：10 × 30 = 300 點。
- 先形狀再處理 3 個入選者：10 × 20 + 3 × 10 = 230 點。
- 少 70 點，約 23.3%；這只是相同候選與可接續端點下的算式，不是實測成品率。網格整理、動畫、轉檔、重試與人工成本尚未包含。

費率依 [Meshy API pricing](https://docs.meshy.ai/en/api/pricing)；分段端點與模型支援須在執行當日確認。不要拿網頁免費的操作推論 API 也免費。

## 最小比較批次

先做一件代表物確認下載、保存、整理與引擎匯入可走通，再擴成同一組六件：簡單道具、帶孔薄片道具、硬邊建築件、裝飾雕件、人形、四足。每家使用相同需求與參考圖，設定相同候選上限與時間上限。樣本少只判斷該批素材，不宣稱全面勝出。

燈灣村第一件建議鐘或提燈；後續再加鐘亭屋簷構件、湯攤器具、角色與灰角獸。鐘亭整體不是單次生成物。人物與怪物測試不能阻塞已合格道具進場景。

建議規劃上限（不是花費授權）：兩家、六件、每件每家至多兩個形狀候選；只有入選件繼續處理。先出精確報價，再依核定總額縮減範圍。每件修整可先設 30 分鐘檢討點，主角另估；到點決定續修或換路，不偷偷增加工時。

## 批次效率與停止

- 初期並行數 1；確認記帳與下載後才在已授權範圍改成 2。一次只開一個批次擁有者，避免多個 agent 用同一額度。
- 提交前先保存請求、輸入雜湊、預估費用；收到 task ID 立即落盤。兩個階段之間插入人工或模型視覺篩選，不把所有任務接成自動付費長鏈。
- 狀態查詢與下載可依服務限制做有界重試；創建任務、貼圖、重建等付費操作不盲重試。超時先查舊 task，失敗後才判斷是否有額度及必要重送。
- 保存模型實際版本與隨機種子。相同 seed 只能改善追溯，不保證廠商更新後逐位元重現；下載的模型才是凍結成果。
- 出現相同缺陷、預算不足、來源授權未知、下載過期、待查帳單或工具版本不符時停止相關步驟；其他已授權的整理工作可繼續。

## UE 驗收

在專用測試地圖使用固定相機與中性光照，保留參考圖並拍正、側、背、近景。必須以最終匯入版本判定。

| 檢查 | 必須保存的結果 |
| --- | --- |
| 幾何 | 實際三角面、物件數、孔洞／黏連／錯法線、輪廓與背面 |
| 尺度與原點 | 公分單位、人物尺度對照、底部／鉸鏈原點、朝向與可動部件 |
| 材質 | 基色、法線、粗糙度、金屬度對應；線性色彩設定、法線方向、貼圖座標與接縫 |
| 碰撞與行走 | 可走區域、門洞、階梯、碰撞簡化；不能只看模型能顯示 |
| 複雜度 | 實際鏡頭距離、遠距簡化、材質槽與貼圖記憶體；Nanite 不免除碰撞及材質成本 |
| 角色 | 骨架對應、站立、走跑、攻擊、轉向；手指、肩肘、膝蓋、衣物穿插 |
| 重開 | 保存後關閉測試場景再讀回，沒有遺失貼圖或外部絕對路徑依賴 |

按專案硬體與場景負載設定面數／效能門檻，不硬套通用 30k。沒有跑效能就標未測。不可只用 AI 自評打勾。
