# World Labs 生成前準備

先讀 [查證與控制方式](references/controls.md)。共用知識原稿及閱讀版在 `/home/cash/Knowledge/3d-production/world-generation/`；不要把共用方法複製進遊戲 repo。與 `online-3d-assets` 並用時，World Labs 的輸入和單次候選限制以本技能及使用者當次要求為準。

## 先選路線，再準備圖

- **延伸現有世界**：先查原始 world ID、模型、帳戶是否能在 Marble 打開並使用 Expand；不能只從本機 SPZ 推定可延伸。Expand 不支援 Marble 1.1 Plus；網頁權限、當次報價與輸出方式先驗，公開 v1 生成端點不是 Expand。
- **新建單一空間**：有一致實景或渲染視圖時用多圖；只有一張概念圖時，別另外獨立生成幾張圖冒充同一空間。可先在本機建簡單布局，統一相機、建築位置與光照後產生參考。
- **尺寸與道路必須可控**：先做有實際尺寸的簡單 3D 布局，查帳戶 Chisel 支援與價格；可載 GLB／FBX。生成只是布局引導，不保證原網格或雕紋保真；精細 GLB 在成品中另行保留。
- **多個互不相見的區域**：分區後用 Compose 或本機引擎拼接。先固定門口尺寸、地面高度、朝向與光照；平面配置圖只供布局參考，不是自動建完整多房間世界的輸入。

## 生成前交付包

在專案產物目錄保存一份計畫，至少包含：

1. 玩家能走到哪裡、最近觀看距離、是否能上船／上屋頂、出口接到哪裡；無資料的背面與頂部明列待補。
2. 選定路線、網頁或 API、模型版本、帳戶功能查核與依據日期。不得混用 Atlas beta 與 v1 欄位。
3. 每張輸入的路徑、SHA-256、尺寸、來源、相機位置／朝向、重疊對象，以及光色與固定物件一致性檢查。視角未知就標未知，不填假角度。
4. 固定風格、地面高度、出口尺寸、共同地標、禁止改動項；提示詞不能代替幾何控制。不要將模糊舊場景截圖當清晰材質來源。
5. 離線準備請求並逐欄核對官方 schema；只有本機流程支援的選項才可使用。假 ID／範例檔不能送出。
6. 模型費、輸入處理費、匯出費分列；記既有支出、進行中預留與總上限。本案預設一個正式候選、零自動付費重試，不先做付費草稿；使用者另有明示才改。
7. 保存位置、第二份備份位置、驗收路線與失敗處置。計畫未完成就報缺項，不宣稱可一次成功。

## 支出與恢復

研究、生成計畫或提供 API key 都不等於本次支出授權。沿用已明確核定的範圍與上限；缺少時準備到可審查的請求、圖與完整估價後再確認。不得因剩餘點數足夠、關閉自動儲值或預設重試便啟動付費。

送出前保存請求雜湊；收到 operation ID 即落盤。逾時先查既有任務與費用，不重送生成。不要假設 v1 支援 beta 的 Idempotency-Key。下載失敗只恢復下載，不重生世界。保存原輸入、完整結果 metadata、全景、SPZ 各解析度、碰撞模型及已有匯出；核對雜湊、讀回第二份備份，未做備份不能說不會遺失。

## 驗收與停止

先驗可走路線，再驗出口、近景、側背面與可登上的頂部；固定位置拍前後圖。畫面與碰撞分開驗，阻擋需在劣化區之前；邊界只是限制活動範圍，不能列作畫質修復。

形狀正確只需接縫、位置、光色或碰撞調整時先本機修。新候選出現缺面或模糊時保存證據並分析，不自動第二次生成。未證實根因要標假說；多圖、全景與 Chisel 都不保證一次成功，也不等於 4K／獨立 VR 已驗收。
