# 派工與路由

## 本機 Essence 專用：本機 AI 執行（使用者 2026-09-28 定，優先於下方一般判準）

只在主機 `Essence`（`hostname` 為 Essence）適用；同一 repo 在別台電腦不適用。這台電腦上所有 repo（ICO、DnaBoss、private、newretail 等）都要遵守。

- 所有工作由監督者（雲端模型）拆解後派給本機模型執行：讀檔、搜尋歸納、寫程式、改文件、審查、測試分析。監督者負責拆題、驗收與最終判斷，不自己包辦可派出的工作。
- 入口：`localai code|review|second`；預設關閉隱藏推理並限制輸出長度，需要時才加 `--think`。可自由安裝或更換本機模型，但先查 `python3 ~/tools/ollama_management/status.py`，不得繞過 `ollama-memory-gate` 與服務的 CPU／記憶體上限；CPU、記憶體都不可推到 100%，保留桌面與其他服務餘裕。
- 模型輸出一律視為待驗證的線索；關鍵判斷、金額、權限、刪除、部署仍由監督者以工具輸出驗證。本機模型逾時或失敗先查原因（載入、推理長度、上下文），不盲目重送。
- 降級（使用者 2026-10-01 定）：能用確定性工具機械回答的問題（搜尋、計數、編譯、格式檢查）直接用工具，不必派模型。本機模型服務不可用時，繼續已授權的只讀工作；需要模型的寫入工作，有任務層級授權才可改派雲端代理，否則標 BLOCKED 並回報。不得自行重啟、卸載或繞過共用模型服務。
- 犯過的錯寫進 `~/.agents/lessons.md`（一條一個錯、原因、防止方式），每次開工先讀；同樣的錯不得再犯。
- 可重複使用的程式、Shell、腳本一律做成 SKILL＋MCP，放在 `~/work_space/private/mortal-mcp`，並登記 `~/tools/tools.json`。

## 一般判準

派工不採固定的「本機優先」或「最強模型包辦」（Essence 以上節為準）。先用確定性工具回答可機械驗證的問題；需要模型時，選能在授權與品質要求下完成任務、預期總成本最低的執行者。

## 路由判準

估算各可用路徑的預期總成本：執行成本 + 背景整理／交接 + 驗證 + 預期返工 + 錯誤風險。時間、用量、隱私與錯誤後果都可納入；資料不足就明記判斷不確定，不做虛假精算。

- 關鍵判斷、資料正確性、權限、金額、刪除、正式部署等高風險工作，直接安排足夠能力的模型／人員負責；可另派本機模型做反方意見，但不能當決策者。
- 本機模型適合大量讀取、草稿、重複修改或本機資料處理，特別是原始資料不應離開本機時。若上下文往返、驗證或返工成本較高，可直接選能一次完成的雲端模型。
- 計畫只記本輪必要的工作、風險／難度、執行者、選擇理由和驗證方式。記錄實際執行者；沒有真的派工就不能寫已派工。
- 優先只傳差異和必要背景。模型回覆是待核對的線索；結論要能定位到 Git SHA、檔案、符號／測試或命令輸出，行號僅作輔助。

## 本機模型的持續使用

模型角色、近期能力和近期表現可能改變，不將固定型號或單次分數寫成永久結論。評估模型時按同一任務類型比較近期樣本，並分開記 `used`（直接採用）、`edited`（修改後採用）、`rejected`（未採用）。

- 只有同一 task family 的可比任務才進同一組；至少有 3 筆近期樣本才用平均分或採用率改變預設路由。樣本數不足時保留人工判斷。
- 單一低分不自動換模型；連續低分只有在同類任務中才觸發重新評估。若出現資料外洩、捏造證據等重大失誤，立即停止該角色的相關工作，不需等待累積樣本。
- 新模型比較應用同一輸入與同一驗收條件；記錄資料版本、評分者及結果。回顧測試不是新盲測，不得這樣宣稱。

## 外部資料與「查無」結論

宣稱「找不到公開測試／來源」時，checkpoint 將 `search_conclusion` 設為 `not_found_within_scope`，並記 `searched_at`、實際查詢字串、來源清單、搜尋範圍和限制。只可下「在已列範圍未找到」的結論；沒有搜尋證據時標未查證，不寫成不存在。

## 外部研究的使用界線

文獻中的成本或品質數字只代表該研究的模型、資料、任務與設定，不直接證明本機模型或目前路由更省。需要引用時提供來源與可重現搜尋資訊；無法確認來源時只保留待查問題，不保留未驗證的數值宣稱。
