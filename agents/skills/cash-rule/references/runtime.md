# 執行、鎖與看門狗

LOOP 是狀態與決策，不是背景程序。只有明確使用本機制的持續任務才設定喚醒；一般回答與短任務不建立排程。

## 事件優先、定時保底

必定檢視的事件：開始、iteration 完成、step 完成、重大錯誤、使用者更正、新證據、阻塞。長時間無事件時，才用看門狗檢查本機進度、停滯、偏離與新阻塞。

- 預設間隔為 15 分鐘；高頻監看、短時效風險或使用者指定時才可用 5 分鐘，並記理由。
- 長命令不因看門狗到點而中斷；在安全接點補做一次並記延誤。
- 看門狗不重跑完整測試、不當外部連線重試器，也不能取代 iteration／step 的驗收。

## 設定與所有權

1. 先查同一工作目錄、主 LOOP 是否已有 owner、goal、排程與鎖；有就沿用。
2. Codex goal 與定時喚醒不同；建立 goal 要使用者明確要求。先讀當前工具說明，不猜指令。
3. 沒有可用排程、登入或執行權限時，記為「未啟動背景循環」，仍完成前台可做的工作；不得用 shell `while` 迴圈替代。
4. 任務識別採工作目錄與主 LOOP 絕對路徑；子 LOOP 共用主 LOOP 的 owner、排程與停止條件。
5. 喚醒者只用暫存檔加改名留下檢視要求；確認 owner 後才取得鎖並寫 LOOP。忙碌時只留提醒，不開第二個寫入者。
6. 排程固定工作目錄、明確 executable、非互動 stdin 與獨立本機日誌；不加入繞過權限旗標。外部操作失敗即停止該操作並記錄。

## Owner lease 與 stale recovery

需要跨喚醒續行且會寫共用狀態時，鎖紀錄至少包含 `task_id`、`owner_id`、`acquired_at`、`heartbeat_at`、`lease_until` 與遞增的 `lock_version`。`owner_id` 要能對回具體 session／程序；跨主機工作優先用儲存服務原生 lease/條件更新。

- lease 時長依最長不可中斷工作設定；執行者在 lease 到期前續租，建議每 `lease_duration / 3` 更新一次。長命令在安全接點更新，不能為續租而重啟命令。
- lease 到期只代表「可能 stale」，不能單獨證明 owner 已死。回收前同時檢查心跳已過期、owner 程序／session 不存在或已明確 relinquish，並用原子條件比對舊 `owner_id`／`lock_version` 後才接手。
- 若仍無法確認 owner 是否存活，轉 `WAITING` 並留檢視要求；不要搶鎖或同時寫 LOOP。鎖回收要記錄舊 owner、過期時間、判定依據、新 owner 與新版本。
- 正常完成、取消或交接時由 owner 釋放 lease。程序非正常結束時不刪鎖檔；依 stale recovery 規則處理。

## 喚醒提示範本

> 讀技能、主 LOOP、當前 step 與專案規則；核對 owner、實際證據與未完成驗收。
> 若有人執行，只留下檢視要求並退出。否則在既有授權內接續最小必要動作。
> 事件或看門狗觸發時只檢視停滯、偏離、新阻塞與證據有效性；有新證據才重排。
> 每個 iteration／step 仍須獨立驗收並寫 checkpoint；一般完成後只停止本任務的排程。

## 啟用驗證

- [ ] owner、主 LOOP、間隔、鎖與停止條件可查。
- [ ] 第一次實際喚醒有時間與日誌，且讀到正確的主 LOOP。
- [ ] 忙碌時只留提醒，未開第二個實作者。
- [ ] owner 處理提醒後更新 checkpoint 或最近檢視時間。
- [ ] 停止只影響本任務；未以喚醒偽裝失敗重試。

新安裝或改寫技能後，已開啟工具可能仍用舊描述；另開工作階段才可驗證入口載入新版本。
