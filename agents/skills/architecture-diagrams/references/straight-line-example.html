原規劃進度｜依風險與依賴分六階段

依 2026-10-23 原文件保留文字重畫，2026-10-26 恢復；不是原 PDF 的逐位元復原，也未重新驗證今日部署。

保留原文件 9–12 週估算，非今天的交付承諾。每階段須先達驗收條件，再進入下一階段。

階段 0｜第 1 週　基準與邊界

先量出問題，避免先造大型平台。

  • 固定 20 個真實任務
  • 記錄遠端每步延遲、成功率與成本
  • 固定敏感資料、核准與停止規則
完成門檻：可重跑的基準報告；每個失敗可定位在模型、工具或畫面辨識。

階段 1｜第 2–3 週　自家 Client 最小版

先把 Agent Loop 跑通，不做記憶與本地模型。

  • 任務輸入、串流、Tool Call
  • Shell／檔案／MCP、核准與取消
  • 經現有 Gateway 呼叫遠端 LLM
完成門檻：5 個程式任務可連續執行、可中止、工具結果可追溯。

階段 2｜第 4–5 週　上下文與資料品質

讓長任務不靠無限堆疊對話。

  • Session Store、Token 預算
  • 摘要壓縮與來源引用
  • 文件解析、去重、搜尋、Reranker
完成門檻：壓縮前後任務成功率不下降；引用能回到原始資料。

階段 3｜第 6–7 週　本地模型派工

只接能證明比遠端快或便宜的工作。

  • vLLM／Ollama Provider
  • Qwen 視覺與程式模型
  • OCR、分類、GUI 定位、短摘要
完成門檻：指定任務 P95 延遲與成功率達標；不達標就維持遠端。

階段 4｜第 8–9 週　Computer Use

先介面樹與 API，再用畫面座標補洞。

  • 截圖、介面樹、Playwright
  • 點擊／輸入／捲動／結果驗證
  • 高風險操作強制核准
完成門檻：10 個桌面流程成功率達 80%，錯誤不造成不可逆動作。

階段 5｜第 10–12 週　按需雲端 GPU 與收斂

有數據後才接租用資源與自動關機。

  • GPU 啟停、暖機、佇列、閒置關機
  • 成本上限、失敗回退、資料區域
  • 全流程評測與操作手冊
完成門檻：租用成本可預測、閒置自動歸零；真實流程優於純遠端基準。

估算邊界：一位主工程師；不含模型訓練、正式多租戶內容保存與大規模 GPU 採購。
