# 每輪工作步驟

這份技能只做路由，不新增授權。語言、白話、篇幅、證據、授權、最小實作、PDF 底色等共同規則以 `~/.agents/RULES.md` 為準，開工時已載入，這裡不重述。使用者當前指示與專案規則優先。已由掛勾載入本段時直接套用，不必每輪宣布使用技能。

## 先判斷本輪要做什麼

依目前訊息及前文判斷，不用關鍵字猜，不把追問當成新任務。
- 問答、翻譯、改寫：直接回答，只套語言、範圍與事實規則。
- 開程式、開網頁等單次操作：執行已授權動作，確認目標畫面或狀態；不建 LOOP、不查無關 repo、不跑工程測試。
- 研究、評估、診斷：查證並回報；未要求修改就不自行實作。
- 程式、設定或系統修改：執行下列最小完整修改步驟。
- 需求不清楚或工作太大：先讀 `~/.agents/skills/cash-rule/references/intake.md` 問清楚並拆票，再動手。
- 長時、多步或跨輪工程：再讀 `~/.agents/skills/cash-rule/SKILL.md`，沿用現有任務與驗收；短任務不建 LOOP。

## 最小完整修改

1. 開工依 `~/.agents/skills/start-work/SKILL.md`：讀適用規則，確認工作區、未提交修改、現有程序與產物，保留他人工作。
2. 先查現有程式及工具，再查內建功能與已裝套件，最後才新增程式。沿用專案分層與慣例。
3. 一次完成需求涉及的呼叫端、設定、測試與文件；少寫程式不能變成漏做需求。保留驗證、錯誤處理、安全與可及性。
4. 先跑能推翻修改正確性的最小檢查；修錯附陰性對照與覆蓋邊界。提交前格式化、靜態檢查、測試皆過，推送或 PR 前依專案跑全套。已通過且無新疑點，不重跑。

## 專項能力按需選用

- HTML 或複雜比較與關係需要視覺說明：讀 [answer-me-with-html](../answer-me-with-html/SKILL.md)；簡短問答維持文字。
- 新增模組、依賴、抽象或疑似重複／未用程式：依 [精簡實作檢查](references/code-quality.md)。
- Rust 審查、編譯修復、測試設計讀 [ecc-rust](../ecc-rust/SKILL.md)；PostgreSQL 讀 [ecc-database](../ecc-database/SKILL.md)；API 契約讀 [ecc-api](../ecc-api/SKILL.md)。先讀目標專案規則，三者不取代既有測試與驗收，也不增加授權。

載入、驗證與復原方式見 [接入說明](references/integration.md)，只有維護此技能時才讀。
