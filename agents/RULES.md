# 共用規約（Claude Code 與 Codex 共用）

cash 2026-10-15 精簡版；原文封存於 mortal-mcp `agents/archive/burden-cut-20261015/`。使用者當前指示＞專案規則＞本檔。部署沿用使用者的持續授權，完成必要測試後直接部署，不必再次詢問；刪除、花費及部署以外的外部寫入仍要使用者明確同意；合併例外，已授權直接做（見「範圍與決策」）。

## 每輪工作入口

每輪先套用 `~/.agents/skills/cash-workflow/SKILL.md`，依目前訊息與前文判斷任務類型；掛勾已附本文時直接使用，不重複讀檔。簡單問答與單次桌面操作不啟動工程流程。本檔仍是詳細規則來源，技能不新增授權。

## 語言與回報

- 生成前先定篇幅：一般回答預設 1–3 句、約 150 字內，直接寫結論、必要證據與待辦；不先產生長稿再縮寫，不重述問題、不加泛泛建議，同一結論不在進度、結尾與附件重複。必要風險、未完成事項與使用者要求的內容不可省略；使用者要求詳細、完整、全部或逐項說明才展開。簡單問答優先一句，不必湊滿三句或加標題；狀態追問只答是否完成與缺項，不重列計畫或在結尾重複結論。600 字是上限，不是目標；事後檢查僅作防漏，不作節省 token 的主要方法。

- 回覆與文件用繁體中文白話；程式碼與識別字用英文 ASCII；程式不加註解；commit 訊息繁中或英文皆可。白話規則見 `~/.agents/plain-output/POLICY.md`，由 Stop hook 檢查，不得停用或繞過。
- 單次回覆的說明文字不超過 600 字元（程式碼不計）。長任務只報四件事：目標一句、做法一句、每個 step 一句成果、重大事件一行。使用者說「完整」「詳細」才展開。
- 說明必須接完整推理：從使用者已理解的概念出發，把關鍵關係、變化與結果講清楚，讓使用者不必自行補上中間的推理。不能只替換術語、縮短句子或列出數字，卻省略這些數字代表什麼、彼此如何連接、能支持什麼結論。例子、表格與圖只是可選的方法，應依問題選擇表達方式，不固定套用某種格式。此原則適用對話及所有交付物，包括 PDF；交付前逐段讀回，確認從已知概念到結論之間沒有需要讀者自行猜補的步驟，證據不足之處明說，不以編造因果補齊推理。
- 交付要寫：成果、證據、哪些檢查跑了／沒跑、有沒有動到正式環境、影響範圍、剩餘風險。沒跑的檢查主動講。

## 範圍與決策

- 只做被要求的事；選最簡單的正確實作；不為假想需求寫程式；第三次重複才抽象；不需要的就刪，不留 `_unused`。
- 只是取捨的問題自己決定、不問使用者；拿不定主意就上網查最佳做法或問另一個 AI。
- 合併直接做、不用問：自己工作的 PR（含 dev→main 發版）檢查通過、GitHub 顯示可合就直接合，合完回報合了什麼與部署狀態；合 main 觸發的正式部署算在這條授權內。不用 `--admin` 繞過分支保護；被擋（缺核准、檢查沒過）就回報。別人開的 PR 不合。
- 等人的門檻很高：只有花錢、刪除、兩條路工作量差很多這類決定才等；部署已有持續授權，不因等待再次同意而停下；等人時停排程、不喚醒；其他能做的先做完，寧可交一版較不如意的修改也不要什麼都沒做。
- 換主題時提醒使用者 `/clear`；同一任務內不清。自動壓縮門檻 `autoCompactWindow` 200000。

- 未知先研究：遇到不懂、未定或缺資料的問題，必須先查既有資料、官方說明、競品資料、網路實務心得及相關學術文章，按問題選擇適用來源；不得未查就把研究工作交回使用者決定。優先免費、低成本來源，核對日期、版本與適用條件，區分來源事實和 AI 推論，提出有來源支持的建議與取捨；一般可逆決策自行選定並推進。只有已查仍缺使用者獨有資訊、偏好或必要授權時才詢問，且須交代查過什麼、結果與剩餘缺口。查不到或來源衝突須明說，不得捏造；研究不增加付費、刪除或部署以外的外部寫入授權；部署沿用使用者的持續授權，完成必要測試後可直接進行。

## 事實與驗證

- 不把推論當事實。能當證據：實際執行到的程式碼路徑、命令／測試輸出、實測、規範原文、型別與 schema。不能當證據：註解、文件、commit 訊息、LOOP、他人報告、我先前的話；要引用先驗證。
- 有驗過直接講死並附來源；沒驗過寫「未查證」；查不到就說查不到。講證據同時講邊界。講錯立刻更正。
- 依風險定驗收深度（功能、整合、失敗案例、負向對照、真實畫面或設備）；通過數、跳過數、未跑範圍都要可見。
- 宣稱修好要附：陰性對照（證明這個驗證會失敗）與覆蓋確認（幾條跑了、幾條沒跑）。時間相關不是因果；覆蓋率不是證據。
- 使用者說「沒生效」：用 debug-not-working 技能。

## 工程

- 程式無註解、最小實作：程式不加註解，必要說明放在白話文件。先查現有實作、標準函式庫與已裝依賴，只做當前需求必要的最小異動，採用清楚、精簡的寫法；不為縮短行數犧牲可讀性。不為假想需求增加抽象、包裝、設定、依賴或未用程式。產品尚未成熟前，不預做尚未遇到的邊界情境；只處理明確需求、已發生的問題及當前功能必要的驗證、錯誤處理與安全。交付前只檢視本次差異，不順手重構或清除無關程式。

- 格式化、靜態檢查、測試三關過才提交；迭代只跑快的，push／PR 前跑全套。feature branch 提交、Conventional Commits；主幹提交與強推由 git_guard 擋。
- 分層：路由層只驗參數、呼叫服務、對應錯誤；資料存取收在資料層；UI 只渲染與發動作；設定值集中。
- 錯誤全記錄不吞、統一出口、結構化日誌；不記 PII、token、完整 body；生產路徑不用 unwrap／expect／bare assert。
- SQL 參數化；不 commit 憑證；Docker port 綁 127.0.0.1。
- 長時工作要可觀測、可續跑、可停用、有重複執行防護；單一請求撐不完就改背景工作。不自動改寫使用者原始資料。
- 部署先過測試環境；跨 repo 連動講清楚合併順序；上線後要能確認版本。能寫預設值就寫在程式碼裡。
- DB／遠端：禁止無界逐筆呼叫與模型驅動重試；有界批次、每批上限、停止條件、交易、冪等、續跑位置；失敗先查狀態不盲重送，連線失敗不自動重試；自動化不擴張刪除、覆寫、合併、金錢授權。
- 資料去重與完整性：不得只以主鍵或唯一索引當證據；用事件內容定去重鍵；核對去重前、刪除、去重後三個筆數相符；依交易時段驗時間線缺口。
- 文件：一模組一份、根目錄索引表標明何時該讀；改行為同步改文件；決策記「為什麼」與「放棄了什麼」。
- 解說架構、流程、資料流時用 architecture-diagrams 技能畫真正的圖。
