# 工程政策：範圍、驗收與授權

本文件只定工程邊界；唯一生命週期、狀態和轉換定義在 [SKILL.md](../SKILL.md)。簡單問答不建立 LOOP／排程；評估或診斷先回報，不自行實作；修改任務依明確授權執行。

## 計畫與背景

- 先確認使用者、問題、預期成果、排除範圍與整體驗收，再列依賴與 step；只細拆近期一至兩步。
- 先用最小有界檢查驗證最可能推翻方案的假設。一次推進一個主要 step；阻塞時可做不受影響的工作並記下切換原因。
- 背景包只帶目標、現況、證據、未知、限制、允許動作、完成條件與必要路徑；交接版本與內容識別碼。細節見 [背景與證據](context-policy.md)。
- LOOP 是目前狀態的投影，不是執行器或歷史日誌；小任務可不用 LOOP。主／step LOOP 範本只記各自必要資訊，歷史 iteration 放 checkpoint JSONL。

## 操作與驗收

- 結論必須連到可觀察證據、來源及時間或版本。優先記 Git SHA、路徑、符號／測試名稱、命令與輸出；行號僅作輔助。未驗證、推論、模型意見與舊證據要明確標示。
- 用確定性工具先查能機械回答的問題。依風險決定驗收深度：功能、整合、失敗案例、負向對照、真實畫面或設備操作；單元測試不替代整體驗收。
- 重要結果分開記實作、測試、實際操作、部署與使用者驗收。通過數、跳過數和未跑範圍都要可見。
- 依 [SKILL.md](../SKILL.md) 的生命週期做檢視與重排；證據推翻前提時說明受影響 step 與新增成本。
- 研究、資料、金額、權限或正式驗收工作，使用 [評估規則](evaluation-policy.md) 建立指標、對照、門檻與停止條件。

## DB 與遠端操作

- 禁止無界逐筆呼叫與模型驅動重試。優先用服務支援且有明確大小／時間上限的批次；確認目標範圍，能用交易就用交易，能冪等就使用冪等鍵。
- 分段處理須事先界定每批上限、停止條件與續跑位置。記錄部分成功、失敗、略過筆數與復原方式；失敗後先查實際狀態，不盲目重送。健康檢查／輪詢按服務允許間隔執行，一次喚醒只做有界檢查。
- DB 或遠端連線失敗不自動重試。依錯誤類型和明確安全條件決定是否由 owner 人工重啟；不把限流或封鎖當作可重試錯誤。
- 自動化不擴張刪除、覆寫、部署、合併或金錢操作授權；沿用原 owner、分支、卡、PR 與人工 gate。

## LOOP 與用量

- 長任務主 LOOP 列成果、step、依賴、驗收與當前狀態；step LOOP 只保留該步目前狀態。取消、延後、略過與被新目標取代使用 SKILL.md 定義的狀態。
- 需要跨喚醒續行的任務要記 owner lease；格式、心跳與 stale recovery 規則見 [執行與看門狗](runtime.md)。
- checkpoint 格式、JSONL 位置、通知門檻與 `minimal`／`benchmark` 用量模式，唯一見 [回報規則](reporting.md)。不得要求一般任務逐輪精算 token。
- 交付寫成果、證據、未驗證事項、阻塞與下一步。計時與用量不延誤主要工作；沒有來源就明記 `unavailable`，不估成精確值。
