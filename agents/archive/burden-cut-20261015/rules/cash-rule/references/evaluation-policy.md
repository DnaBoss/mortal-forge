# 評估與流程比較

會影響結果、資料、研究、金額、權限或正式驗收的工作，先定評估契約：問題、主要指標、對照、資料切分、成功／失敗門檻、樣本單位、分析方式與停止條件。評估契約只寫足以判斷任務的內容。

- 指標要對應使用者目標；命令成功、速度、準確率或綠色檢查不能自行替代業務結果。
- 固定資料切分與設定選擇方式；測試資料不得用於訓練、挑參數、挑日期或事後改規則。回顧歷史任務不是盲測。
- 重要評估需有會失敗的負向對照，並依風險檢查洩漏、空結果、極端樣本、重載差異與其他假成功。checkpoint 的 `evaluation_required` 為 true 時，須記錄實際負向對照及結果；不適用時需說明原因。
- 分開記改善、達標、統計支持與可交付；一項不代表另一項。

## Agent 流程 A/B 評估

比較 cash-rule 版本或簡化方案時，使用 20–50 個有代表性的真實任務，先固定任務集、分層方式、驗收規則及停止條件，再開始執行。樣本不足時標為先導結果，不宣稱普遍優劣。

- 按任務類型、風險和難度分層；兩方案使用相同任務、初始資料、工具權限與驗收標準。可配對時配對，並隨機化執行順序；評分者可行時不看方案標籤。
- 歷史任務只在安全的沙盒、錄影／紀錄回放或可還原資料副本中重演。涉及正式寫入、付款、刪除或外部通知的任務，不得直接重送到正式環境。
- 必記：整體完成率、假完成率、未授權／錯誤副作用、人工介入、iteration 數、返工時間、總 elapsed time、上下文／token 用量、本機結果採用率與升級率。
- 以任務為單位比較配對差異，並列樣本數、信賴範圍或限制；失敗任務不得從分母移除。假完成或未授權副作用上升視為安全退步，不用較低 token 抵銷。
- 測試前凍結兩版規則、執行環境和評分表；測試中不得調規則。修改任一項就升版本，另開樣本或清楚標記探索性結果。

## 外部研究與搜尋紀錄

「查無公開測試／來源」只能表示在已查範圍未找到。`search_conclusion` 設為 `not_found_within_scope` 時，使用 `research_search` 欄位記錄搜尋時間、實際查詢、來源、範圍和限制；有作搜尋但未留下紀錄時標未查證，不得宣稱查無。外部研究的成本或品質數字只適用於原研究設定，不直接證明本任務的路由效果。
